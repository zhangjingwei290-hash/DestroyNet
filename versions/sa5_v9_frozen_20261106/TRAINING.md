# 训练、回报与选模

## 训练对象、数据和随机数

本次未执行元训练或16方向单独微调。训练对象是共享Controller（868参数）和Critic（22→32→1、Tanh，769参数）。16个方向原专家均冻结。优化器Adam，学习率3e-4，PPO clip=.2，熵权重.01，价值平方误差权重.5，联合梯度范数上限1。GPU0 FP32用于采集编码和PPO更新，经典修复在CPU执行。

候选池是已生成fit划分180IID，每规模60IID。NumPy RNG seed20261105在每规模不放回抽取6个，实际18个IID。完整清单见 `evidence/TRAIN_SELECTION.json`。第c轮采集seed为20261105+(c−1)，c=1..6。Controller/后续Critic的PyTorch初始化seed20261105。各规模每轮180秒，实例从自己的初始种群开始；不是跨六轮接力同一实例。

## 一轮更新的数据

先以同一Controller参数采集N50、N150、N250各180秒，再执行一次三规模联合PPO更新，包含2个epoch。没有在某个规模采集完成后立即对该规模单独step。每个epoch使用最多1024动作微批累积梯度，收齐整批后执行一次optimizer.step。六轮合计12个optimizer.step。

每条动作按发生时的有效运行比例分到[0,1/3)、[1/3,2/3)、[2/3,1]，正常180秒运行对应早/中/晚60秒。阶段是时间段标签，不是从收益推断的停滞标签。按N×阶段×方向形成144个组合；每轮要求所有组合非空。每个组合总损失权重1/144，组合内动作等权。优势先在各规模内标准化。

## 实际奖励和价值目标

动作t发生前会话最好标量为g_best，动作后的最好值为g'_best，改善为max(0,g_best−g'_best)。实际训练目标为：

```
r_t = [max(0,g_best-g'_best) - v_rate*dt_wave] / (1+abs(g_best))
```

代码的存储字段名仍为 `session_return`，值是上述动作级净收益，不是整场最终得分，也不是五步累计收益。`dt_wave`从该步所有方向状态准备开始，至所有修复future返回为止，包含该步编码/特征/采样、任务提交、修复及等待；结果返回后的逐方向物理复核和接受处理不在这个dt_wave里。一个同步波的各方向共用同一个dt_wave，不使用worker秒数之和。

v_rate来自本run以前已完成会话。保留最近32个方向批次，alpha=2/33，冷启动为0。每个批次用当前动态评分坐标重新评价保存的before/after目标对，取方向会话改善均值/该批局搜墙钟秒数，再按时间顺序做EMA。v_rate在当前整个五步批次内固定，批末更新。它不是未来外层收益的观测值。

Critic输入相同22维状态，拟合r_t。优势是r_t−V(s)，各规模内做均值/标准差归一化。没有GAE、折扣多步return、整场终值回传或赢家轨迹奖励。HV不进入PPO奖励；HV用于选模和离线评测。

## PPO密度

新旧比值同时包含Categorical模式与该模式Beta(u)：

```
logratio = log pi_new(mode) - log pi_old(mode)
         + log Beta_new(u|mode) - log Beta_old(u|mode)
```

微动作客户/路线PL密度由冻结专家在同一重放状态、mode和u下确定，Controller更新不改变这一条件因子；compact重放保存其原logprob，但不对该项求更新比值。整数q映射为确定变换，优化使用潜变量u密度。熵是Categorical熵加按当前模式概率加权的条件Beta熵。

## 验证与选择

每个检查点在validation划分全部45IID各跑180秒，seed20261105；两个检查点共90次。对每个IID两检查点的最终档案共同构造经验ND参考，分别评分，再对45IID等权平均HV。规则只按macroHV选择，精确相等时选较早检查点；代码不使用IGD+破同分。

|检查点|validation IID|平均HV|
|---|---:|---:|
|cycle_3|45|0.9160993668912779|
|cycle_6|45|0.9088272344655803|

选定 `cycle_3.pt`，复制为 `v9_best_gate.pt`。该部署检查点经历前3轮、6个optimizer.step和90080条动作，来自前3轮共9个训练IID。181360是包含第4–6轮的整次训练计数；后3轮形成cycle6等检查点，但不回写cycle3。文件只包含Controller state_dict；与16个冻结原专家组合部署。Critic和optimizer未在本次coordinator中保存检查点，不能由这些Controller文件精确恢复原优化器轨迹。完整compact PPO输入和已记录训练历史已归档。
