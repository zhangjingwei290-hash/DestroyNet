## 第一阶段（Stage 1）：零训练轻量级执行机制升级与验证（`step5_stage1_zero_shot`）

**核心原则**：第一阶段**不修改网络参数、不重新训练**，直接加载 `checkpoints/direction_00.pt .. direction_15.pt`，仅修改推理调度、邻域映射、局部选点与 MOEA/D 量纲归一化，验证纯机制升级的真实收益。

### 1.1 双时间尺度更新：15 微秒 CPU 物理残差更新 + 算力摊销 GNN 刷新（修改 `repo/solver/model.py` 与 `repo/solver/outer.py`）
- **问题根源**：原代码一旦 `last_accepted == True` 就强制重跑全图 6 层 GAT（耗时 `1.7 ms ~ 6.4 ms`），而小邻域（$q=2\sim 5$）修复仅需 `0.2 ms`，导致推理耗时远超修复耗时。
- **具体实现**：
  1. 在 `model.py:node_logits_batch` 中，节点打分由两部分相加构成：
     `raw_logits = values + (physical * physical_weights[:, None, :]).sum(-1)`
     其中 `values` 是 6 层 GAT 输出的慢变拓扑基础分，`physical` 是 `x[:, [18, 17, 19, 12, 13]]`（路径长度占比、客户点局部绕路代价 Detour、最长路径裕度 Makespan Slack、等待时间、延误时间）标准化后的 5 维实时物理特征。
  2. 在 `_tensor_dual_cache` 中，除了输出 `hidden`、$(\alpha, \beta)$ 外，将未加 `physical` 项的 GAT 基础分 `values`（维度 $N$）和 `physical_weights`（维度 $5$）一并打包存入 CPU 缓存。
  3. 在 `outer.py:run_cached_session` 中：
     - 维护 `repair_seconds_since_refresh`（自上次全图 GNN 刷新以来累计消耗的修复算子秒数）、`last_gnn_refresh_seconds`（上次 GNN 刷新耗时）与 `dirty_since_refresh`（自上次 GNN 刷新以来解是否发生过接受更新）。
     - **每当 `session.env.last_accepted == True` 时**：在 CPU 上用 NumPy 仅重算当前 `session.env.routes` 的 5 维物理特征 `phys`（耗时 `< 0.02 ms`），标准化后通过 `logits = cached_values + (norm_phys @ cached_phys_weights)` 除以 `1 + 0.75 * stall_gate` 立即刷新缓存中的 `logits`！这样刚修好的绕路点分数立刻下降，绝不重复拔除。
     - **全图 GPU GNN 刷新触发条件 `cache_refresh_required`**：
       仅在以下情况触发 GPU 全图编码刷新：
       - `session.cached_distribution is None` 或 `session.step_in_session == 0`；
       - 或者 `dirty_since_refresh and (repair_seconds_since_refresh >= 5.0 * max(last_gnn_refresh_seconds, 1e-4))`（**算力摊销准则：保证全图 GNN 推理耗时永远不超过修复算子总耗时的 ~16%**）；
       - 或者连续未接受且 `session.cache_age >= 8`。

### 1.2 跨规模对数点数映射 + 小邻域锚点近邻扩展（修改 `repo/solver/outer.py`）
- **问题根源**：原线性比例 `q = (0.01 + 0.59*u)*N` 在 $N=150, 250$ 上把精修步锁死在 19~31 个点；且小 $q$ 时全图独立 Gumbel-Top-$q$ 抽点会抽出分散在不同路径上的孤立点，重插后只能原位返回。
- **具体实现**：
  1. **对数点数映射（Log-Count Mapping）**：
     在非脉冲步（精修态）下，将模型采样的 $u \in (0, 1)$ 映射为以 `2` 个客户点为绝对下界的对数尺度：
     $$q_{\max}(N) = \min(\lfloor 0.45 N \rfloor, 100), \quad q = \text{clip}\left(\text{round}\left(2.0 \cdot \left(\frac{q_{\max}(N)}{2.0}\right)^u\right), \; 2, \; N\right)$$
     脉冲破局步则映射在 $[\max(6, \lfloor 0.12 N \rfloor), \; \min(\lfloor 0.50 N \rfloor, 120)]$ 区间。
  2. **小邻域锚点空间近邻扩展（Anchor-Neighborhood Expansion）**：
     在 `cached_sample` 中，计算出带 Gumbel 噪声的节点得分 `scores = logits - np.log(exponentials)` 后：
     - 当 $q \le 8$（局部精修）时：先取 `scores` 最高的客户点作为主锚点 $c_1 = \arg\max(\text{scores}) + 1$，从 `session.env.neighbors[c_1]`（空间最近邻有序列表，排除仓库 0）中取出前 $m = \min(N, \max(2q, 12))$ 个空间近邻候选点，再在这 $m$ 个相邻客户点中按 `scores` 从高到低选出前 $q$ 个点（包含 $c_1$）。这保证拔出的 $2 \sim 8$ 个点必定位于相邻的 1~2 条路径交界处，使修复算子能高效完成跨路径边交换。
     - 当 $q > 8$（中大范围重排）时：保持原有的全图 `np.argsort(-scores)[:q]`。

### 1.3 MOEA/D 切比雪夫动态量纲对齐与防克隆替换（修改 `repo/solver/outer.py` 与 `repo/solver/base_environment.py`）
- **问题根源**：`boxes.json` 的静态 `scale` 导致归一化后的最长路线时长 $\tilde{f}_2 \in [0.55, 0.99]$ 比总距离 $\tilde{f}_1 \in [0.03, 0.06]$ 大 15~20 倍，使所有含 $w_2 > 0$ 的 6 个方向全部坍缩去跑最大车辆数，掏空了中间车辆档位（$N=50$ 的 5~7 辆车、$N=150$ 的 11~15 辆车）。
- **具体实现**：
  1. 在 `Search`（`outer.py`）中维护基于当前非支配档案 `self.archive`（及种群 `pop`）的动态理想点 $z^{\min}_i = \min_p F_i(p)$ 与动态跨度 $z^{\text{span}}_i = \max\big(\max_p F_i(p) - z^{\min}_i, \; 0.05 \cdot \text{scales}_i\big)$。
  2. 在 `FixedTchebycheff.do` 与子问题 `env.score` 中，使用动态归一化坐标 $\tilde{F}_i = \frac{F_i - z^{\min}_i}{z^{\text{span}}_i}$ 计算增广切比雪夫标量化值 $\max_i (w_i \tilde{F}_i) + 0.05 \sum_i w_i \tilde{F}_i$，并对超出参考框 `box["reference"]` 的分量施加线性越界惩罚，防止紧时间窗算例（如 `50-1-0`, `150-1-0`）跑出参考框。
  3. 在 `outer.py:MOEAD._replace` 中增加防克隆检查：若新解 `off.F` 与邻域内某槽位现有解的目标向量完全相同（`np.allclose(off.F, pop[j].F, atol=1e-7)`），则不允许继续覆盖其余邻域槽位，确保 16 个方向保持多样性。

## 第二阶段（Stage 2）：解锁跨规模自适应 `q_head` 架构 + 单步时间效率重训与验证（`step5_stage2_retrained`）

**核心原则**：彻底拆除 `model.py` 中把 $q$ 锁死在 `~13%` 的人为手铐，让神经网络直接感知算例规模 $N$、搜索状态与算子开销自主输出 $(\alpha, \beta)$，并用符合文献规范的“单步/短窗口时间效率优势函数”在 FIT 训练集上把 `q_head` 彻底训透。

### 2.1 解锁 `model.py` 的 `q_beta_params` 并统一对数点数动作空间
1. **统一动作映射 `integer_q(u, n)`**：
   在 `model.py` 与 `outer.py` 中统一定义连续动作 $u \in (0, 1)$ 到整数拆点数 $q \in [2, n]$ 的对数映射：
   ```python
   def q_max_for_n(n: int) -> int:
       return max(2, min(int(round(0.45 * n)), 100))

   def integer_q(u, n: int):
       q_max = float(q_max_for_n(n))
       return (2.0 * torch.pow(q_max / 2.0, u)).round().long().clamp(2, n)
   ```
2. **扩充显式规模感知特征并移除三道手铐（`model.py:Policy` & `Head`）**：
   - 在 `q_beta_params` 构建 `state` 时，除原有的 15 维 `struct_state` 与 12 维 `momentum` 外，显式拼接 **4 维跨规模与容量特征**：
     `scale_feats = [math.log(n / 50.0), 10.0 / n, raw[:, 20], raw[:, 14]]`（分别为对数规模、单点步长倒数、当前规模归一化、真实连续停滞比例）。
   - **彻底移除**：
     - 删掉 `base_raw = 0.35 * torch.tanh(...)` 的 `0.35` 限幅；
     - 删掉硬编码的 `self.q_state_mu = nn.Parameter(torch.tensor([.35, .25, -.95, 1.85, -.55, -.75, -.65]))` 及 `-1.15` 偏置锁；
     - 删掉 `base_kappa = 6. + 8. * sigmoid(...)` 的高浓度下界锁；
     - 删掉 `_tensor_dual_cache` 中 `mode_raw[:, 14] = gate` 的二值覆盖。
   - **替换为无约束双头输出**：
     在 `Head` 中使用两层轻量 MLP 直接从 `q_hidden` 预测 $(\alpha, \beta)$（或无约束的 $\mu \in (0.02, 0.98)$ 与浓度 $\kappa \in (2.0, 20.0)$）：
     ```python
     mu_logit = self.q_mu(q_hidden).squeeze(-1)          # 无 0.35*tanh 截断！
     kappa_raw = self.q_kappa(q_hidden).squeeze(-1)
     mu_prop = 0.02 + 0.96 * torch.sigmoid(mu_logit)
     kappa = 2.0 + 18.0 * torch.sigmoid(kappa_raw)
     alpha = 1.0 + mu_prop * kappa
     beta = 1.0 + (1.0 - mu_prop) * kappa
     mode = ((alpha - 1.0) / (alpha + beta - 2.0)).clamp(1e-3, 1.0 - 1e-3)
     ```
3. **CPU 端实时微秒级 `q_head` 推理**：
   - 在 `outer.py:run_cached_session` 的每一步中，图嵌入 `hidden`（128 维）和节点基础分 `values` 从缓存读取，但 `q_beta_params`（仅涉及 1D 向量运算，耗时 `< 0.02 ms`）**每一步都传入当前最新的 `raw`（含最新停滞步数 `stagnation`、当前选中的修复算子 `repair_id`、剩余时间预算）和最新 `struct_state` 实时计算 $(\alpha, \beta)$**，彻底废除外部写死的 `pulse_required` 节拍器！

### 2.2 改造 `repo/solver/training.py`：单步时间效率信度分配 + 短窗口高效训练
- **问题根源**：原 `training.py` 将 10 秒（约 1,000 步）的奖励总和平均分摊给每一步，导致 $q$ 的信度分配严重失真；且 10 秒窗口导致 30 分钟内每个方向只能更新 1~4 次。
- **具体改造**：
  1. **热启动加载**：从 `D:\WorkSpace\fuxian\DPR\runs\experiments\v5_fix_verification_20261030\checkpoints\meta_complete.pt` 加载已训好的 6 层 GAT `encoder`、`context`、`film`、`node` 与 `physical_bilinear` 权重；对新增/修改的 `q_body`、`q_film`、`q_mu`、`q_kappa` 进行中性初始化（使初始 $\mu_{\text{prop}} \approx 0.35, \kappa \approx 4.0$，覆盖小、中、大邻域以便充分探索）。
  2. **单步/短视界时间效率优势函数（Time-Normalized Step-Efficiency Advantage）**：
     在 `group_advantages(episodes)` 中，不再给整条轨迹的所有步赋同一个常数 `adv`，而是结合**轨迹级相对优势 $\hat{A}_{\text{traj}}$** 与**单步时间效率优势 $\hat{A}_{\text{step}}$**：
     - 对每一步 $t$，计算其真实耗时 $\Delta t_t = \max(t_{\text{inf}} + t_{\text{rep}}, 10^{-4})$ 与非负目标改进 $r_t = \max(0, \text{reward}_t)$；
     - 定义单步时间效率 $e_t = \frac{r_t}{\Delta t_t + 0.002}$，并计算 4 步折扣效率回报 $G_t = \sum_{k=0}^{3} 0.8^k e_{t+k}$；
     - 在同一 `start_group`（4 条同起点副本轨迹）的所有步上对 $G_t$ 做均值方差标准化得到 $\hat{A}_{\text{step}, t}$；
     - 若处于深停滞状态（`stagnation >= 6`）且当前步破局成功（$r_t > 0$），额外给予破局奖励加成；若 `stagnation <= 3` 且选了超大 $q$ 导致耗时 $\Delta t_t$ 远超均值却零改进（$r_t = 0$），给予时间浪费惩罚；
     - 最终每步优势为：$A_t = 0.4 \cdot \hat{A}_{\text{traj}} + 0.6 \cdot \hat{A}_{\text{step}, t}$。
  3. **缩短采样窗口 + 分层学习率确保彻底收敛**：
     - 将训练采样窗口从 `10.0s` 调整为 `2.5s`（在相同时间内采样组数与梯度更新次数提升 4 倍，涵盖 $N=50, 150, 250$ 的平衡 FIT 算例）；
     - 冻结底层 6 层 GAT（`encoder.gat_*`），使用 Adam 分组学习率：`q_body, q_film, q_mu, q_kappa` 设为 `lr = 3e-3`，`node, film, physical_bilinear` 设为 `lr = 3e-4`；
     - 元训练阶段至少跑满 **60 个 meta batches**，16 方向自适应阶段保证每个方向至少完成 **15 ~ 25 次梯度更新**（总训练时长控制在 45 ~ 75 分钟内）。
  4. **训练收敛自检（Gate Check）**：
     训练完成后，编写自检脚本打印 16 个方向权重的变化范数 `||Δq_mu.w||`，并固定输入 $N=50, 150, 250$ 及 `stagnation = 0, 2, 8` 测试模型输出的平均拆点数 $\mathbb{E}[q]$ 与比例 $\mathbb{E}[q]/N$，确认模型确实学会了：
     - 在 `stagnation = 0`（精修态）下倾向于输出小点数精修；
     - 在 `stagnation = 8`（停滞态）下自动放大 $q$ 破局；
     - 在 $N=150, 250$ 上精修期的相对比例 $q/N$ 显著低于 $N=50$。
